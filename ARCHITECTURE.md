# Architecture — Steel Vanguard

## Layers

```
Browser shell (main.js)   wiring, save/score sync, debug API exposure
        │
Fixed-timestep loop (loop.js)     60 Hz logic ticks, rAF render batches
        │
Core simulation (game.js)  ─ pure logic, runs in Node, seeded RNG
        │
   ├─ state-machine.js     BOOT…VICTORY states + legal transitions
   ├─ collision.js         swept shells, rigid tank movement, map rules
   ├─ map.js               26×26 tile world + brick quadrants + base walls
   ├─ ai.js                enemy decisions (goal scoring + throttled BFS)
   ├─ levels.js / level-validator.js
   ├─ entities/            tank/player/enemy/bullet/powerup/effects
   │
Browser-only (never imported by the core)
   ├─ renderer.js  Canvas pixel art, cached terrain layers + tank sprites
   ├─ input.js     per-player keyboard state, hold vs press edges
   ├─ audio.js     lazily-created AudioContext, synthesis-only SFX
   └─ ui/          menu model + HUD view builder
```

The hard rule: **game rules never touch the DOM/Canvas**. `tests/` instantiate
`src/game.js` directly in Node; the browser builds the same objects and feeds
keyboards/frames into them.

## Main loop & fixed timestep

`loop.js` accumulates wall time and runs `game.update(1/60)` at most
`MAX_FRAME_CATCHUP` (8) times per animation frame; excess backlog is discarded
so a stall (tab switch, paused debugger) can never teleport a tank through a
wall. Rendering happens once per rAF, fully decoupled from simulation rates.

## State machine

`BOOT → MAIN_MENU → STAGE_INTRO → PLAYING ⇄ (PAUSED / PLAYER_RESPAWN) →
STAGE_CLEAR → SCORE_SUMMARY → {STAGE_INTRO | VICTORY}`, plus `HELP` and
`GAME_OVER` exits. Illegal transitions throw (`state-machine.js` TRANSITIONS
table), which the test suite exercises deliberately. `PAUSED` is a real state:
every timer, animation phase and shake source inside `update()` branches off the
state, so pausing freezes logic, power-up countdowns and enemies with zero
special cases.

## Entities & lifecycle

Players, enemies, shells and power-ups are plain data classes
(`src/entities/`). Game.js owns every array and prunes the dead at the end of
each world tick (`enemies = enemies.filter(alive)`), shells likewise. Effects
use fixed-capacity ring pools (`Effects._push` recycles the oldest entry), so
object churn and memory stay flat no matter how loud a frame is.

Entity IDs are monotonic (`nextEnemyId`) and drive the debug `damageTank(id)`
API and per-owner shell budgets.

## Collision

- **Tanks** move axis-aligned at ≤ 1 px/step, far below the 16 px tile size, so a
  single per-step clamp is exact. `moveTankRect` clamps against:
  1. field bounds,
  2. blocked terrain (brick by-quadrant, steel, water, base),
  3. other tanks (perpendicular overlap + axis clamp; no interpenetration).
  Lane snapping: switching axis snaps the perpendicular coordinate to the 8 px
  lane grid when free, so 32 px tanks line up with 16 px corridors.
- **Shells** advance in 4 px sub-steps (`BULLET.step`), so even a 400 px/s shell
  cannot tunnel a 16 px wall: every sub-step re-checks bounds, map cells and
  tanks. Shell-vs-tank sweeps are interleaved with map sweeps through an
  `onSubstep` callback so damage order is deterministic (array order, tanks
  before players).
- Brick cells are 2×2 quadrants (8 px); a shell destroys exactly the quadrants
  its 6 px body overlaps, then the cell collapses to empty only when zero
  quadrants remain. Definite order, no double hits, no ghost collisions.

## Map & levels

`GameMap` stores terrain codes per cell plus a quadrant bitmask for bricks and
derived sets: base cells, base defence ring (the shovel's fortify/restore
snapshot), enemy spawn areas, player spawn anchors. Levels are generated by
seeded `mulberry32(hash('tank-battle level N v1'))`:

- mirrored structure (left half → right) with 5 rotating layout archetypes,
- steel/water/grass/ice budgets ramp with the stage number,
- protected zones (base ring, spawns) are never overwritten,
- a validator (`level-validator.js`) proves each stage: spawn points clear,
  base exactly once, 20-enemy queue, ≤ 42 % impassable, BFS route from every
  spawn area to the base ring and from each player spawn to open field.
  Generation is deterministic, so the validator is *proof*, not a filter.

## Enemy AI

Each enemy keeps its own decision cadence (0.5–1.5 s, type-weighted and
seed-offset per tank):

- goal scoring: `power` chases players/base aggressively, `basic` splits 40 %
  player / 20 % base / random, `fast` leans on wander with scouting bursts;
- blocked movement re-decides immediately with a shorter window;
- a stuck watchdog forces a random heading after 45 motionless ticks;
- armour tanks additionally run a **BFS recon** (26×26 passable grid, brick
  counts as passable) toward the base at most once per 45 ticks — never per
  frame, never for every enemy;
- firing is probabilistic with a big boost when lined up with a player or the
  base; each enemy may keep exactly one shell alive.

Enemy cadence desync is derived from the seeded RNG (spawn order offset), so
two runs of the same stage produce the same "swarm" but never lock-step moves.

## Audio

`AudioEngine` creates exactly one `AudioContext` on first receipt of a user
gesture and never rebuilds it. All SFX are oscillator/noise graphs built at
trigger time; a per-clip rate limiter (30 ms) keeps machine-gun fire from
clipping. The engine hum is a single persistent oscillator toggled by movement.
Mute + volume persist via storage; a missing/broken AudioContext degrades the
game to silent without affecting logic.

## Storage

`storage.js` wraps localStorage behind try/catch with a memory fallback (also
the Node path). Saves are versioned JSON; fields are clamped/whitelisted at
load, corrupt JSON falls back to defaults, and CLear DATA restores defaults.

## Determinism & tests

- Core uses only `Rng` (mulberry32) + integer tick counters; no `Math.random`,
  no `Date.now`, no floating frames-of-reference in rule decisions.
- Multi-frame rendering, stalling and input polling can therefore never
  change a match's outcome — proven by the `deterministic-simulation` test:
  same seed + same input script ⇒ bit-identical JSON snapshot after 3600
  frames; NaN/Infinity scans; world-bounds and pool-bounds checks.
- `node:test` suites cover collision, damage, power-ups, spawning, stage flow,
  the level validator and determinism. 52 assertions-generating tests, zero
  third-party dependencies, plain `npm test`.

## Debug interface

`?debug=1` exposes `window.__TANK_BATTLE_TEST__` built directly onto the live
`Game` instance (no side-channel state), giving automation a synchronous
`stepFrames` and a JSON-safe `getSnapshot()`. Without the query parameter the
API is never created, and no normal path consults it.
